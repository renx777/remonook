# Visual notes: design review and implementation

## Findings and decisions

| Area | Friction found | Implemented behavior |
| --- | --- | --- |
| Mermaid insertion | The action inserted raw syntax without helping users choose a diagram or understand the next step. | “Create diagram…” and `/diagram` open a guided composer with six templates, editable labels, advanced Mermaid source and live preview. |
| Diagram revisions | Editing required returning to a fenced source block. | Each rendered diagram has an Edit diagram action. The source remains ordinary fenced Mermaid, retaining existing Pele rendering and Mermaid compatibility fallback. |
| Small screens | Desktop popover positioning and automatic search focus can crowd the viewport and summon the keyboard immediately. | Bullet actions use a Radix modal bottom sheet below 651px, with a visible close action, scrollable content, safe-area spacing and visual viewport tracking. Opening focuses the panel; tapping search opens the keyboard. Desktop keeps its anchored Radix Popover. |
| Image occlusion | Creation lacked a clear draw/adjust/preview sequence and precise region controls. | Separate drawing, selection and card preview modes, move/resize handles, zoom, percentage fields, region labels, undo/redo and answer reveal. Stable region IDs retain existing review progress. |
| Drawing | Notes had no integrated sketch workspace. | “Draw with Excalidraw…” and `/drawing` open a full-screen canvas. An editable PNG is attached to the note; Edit drawing restores its embedded scene. |

## Interaction details

The diagram composer uses a split editing/preview workspace on desktop and Edit/Preview tabs on phones. Label fields avoid requiring syntax knowledge for the starter flowchart and sequence templates. Templates with structural editing needs expose their source. Switching templates preserves each draft during the current session. Invalid source stays available for correction; insertion waits for a successful preview. Keyboard users can navigate mobile tabs with arrow keys, Home and End.

Diagram updates preserve the surrounding note and rich-text ranges. A known occurrence can be edited even when another identical diagram exists. If concurrent source changes make the intended replacement ambiguous, the new diagram is retained automatically as a child version instead of overwriting the other edit.

Occlusion supports dragging with pointer capture and cancel recovery. Arrow keys move a focused region by 1%; Shift increases the step to 5%. Resize handles offer the same keyboard steps. Delete removes the region; the last deletion returns to drawing mode. Card preview uses the same masked-image component as study. Changing hide-one/hide-all mode resets reveal state. Saving follows the existing occlusion and study-deck persistence paths.

Excalidraw exports PNG with embedded editable scene data, limited to 2 MB and 3,000 elements. Editing saves an additional version and retains the original attachment, preserving concurrent changes without a new sync schema. The canvas, image preview and scene all use existing account-scoped media storage, attachment budgets, backups and automatic sync. Export or storage errors retain the open editor. Unsaved changes require explicit discard. A large viewport width change fits the drawing back into view.

## Libraries, loading and privacy

- Excalidraw 0.18.1 provides the canvas engine, shape/text tools and editable scene export. Its JavaScript and styles load only when opening the drawing workspace.
- Radix Dialog 1.3.1 supplies mobile sheet focus containment, dismissal and accessibility. Desktop continues to use Radix Popover; existing selection palettes continue to use Floating UI.
- Pele 1.12.0 remains the primary Mermaid renderer, with existing limits and compatibility fallback.
- Fonts and library assets are served locally. The Excalidraw font directory is generated by postinstall, with accompanying notices. Drawing chunks are excluded from the initial offline shell; chunks and fonts are cached when used. First use still requires their assets to be available.
- No external drawing service, separate account or collaboration backend is introduced. Library notices are retained in LICENSES and THIRD-PARTY-NOTICES.md.

## Validation and release

Model tests cover guided label changes, formatting offsets, exact repeated-diagram edits, concurrent source preservation, and bounded occlusion geometry. Mobile interaction tests cover focus, search keywords, nested Escape and keyboard viewport changes. Existing image-tools app tests cover creation, persistence and studying occlusion cards.

Chromium checks use synthetic local notes and images. The browser scenario exercises diagram create/edit, occlusion movement/resize/preview/save, mobile actions and composer, and Excalidraw PNG save/reopen. Screenshots are reviewed separately because overflow assertions alone do not establish a good layout. Real-device touch, platform keyboards and assistive technologies require additional device coverage; desktop Chromium emulation cannot establish universal accessibility or device compatibility.

The release must pass TypeScript, production build and the full regression suite. Staging is the release target for this branch; production publication requires the separate environment-parity workflow described in ENVIRONMENTS.md.
